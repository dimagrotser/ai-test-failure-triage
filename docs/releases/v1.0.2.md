# failtriage v1.0.2

Changes since v1.0.1. Inputs, outputs and permissions stay as they were, see the [v1.0.0 notes](v1.0.0.md). `@v1` moves to this release. You can also pin `@v1.0.2` or the commit SHA.

## What changed

- **Haiku works as the `model` input** (#82). Every request carried an `effort` parameter that `claude-haiku-4-5` rejects with a 400, so each call failed and the groups fell back to the rules without a word. The parameter is now left out for Haiku, and Sonnet still gets it.
- **The report says why a group was left to the rules** (#85). The line under such a group used to be the same for three different reasons. It now says that no API key was available (also on fork and Dependabot runs), that the group was left out because a run sends only its largest groups, or that the call failed, with the error class and the status, for example `the request failed: AuthenticationError, HTTP 401`. The JSON report has the same as `llm_skip` on the classification. `schema_version` stays 1, the field is optional.
- **A model that overrules a group that passed on retry cannot say `high`** (#84). The sample showed Sonnet naming a bug of the change for flaky groups with a reason that quoted the diff, and answering with `high` against the high verdict of the rules. When it names another category for such a group, its confidence is now at most `medium`. The category is never changed.
- **`failtriage eval` warns when a model made no successful call** (#83). The output starts with a warning that names the model, lists the reasons of the failed calls, and the command exits with 3 after it has written the report and the JSON. Before, a run with an out of date key looked like a normal run. The Lab also has three flaky cases where the cause is not in the diff (#91).

## Known limits that changed

- Accuracy is still a rough guide. On 52 labeled groups, 51 from a small test app I wrote and one real failure, the rules get 60% right, the rules plus Sonnet 75% and the rules plus Haiku 69%. Sonnet gave the same answers in two runs, Haiku did not. Sonnet's `high` answers were right 23 times out of 24.
- Haiku is cheaper, about $0.0028 per group against $0.0076, but I would not trust its confidence. It answered `high` for 46 of 52 groups and was right on 35, 76%, and it said `unknown` once, so for most of the groups labeled `unknown` it named a cause anyway. Sonnet stays the default.
- With the cause of a flaky test outside the diff, Sonnet kept `flaky` for 2 of 3 groups and Haiku for all 3. Three groups say little. The details are in [docs/lab.md](../lab.md).

Everything else under "Known limits" in the v1.0.0 and v1.0.1 notes still applies.
