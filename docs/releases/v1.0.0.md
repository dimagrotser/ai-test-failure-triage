# failtriage v1.0.0

First release. After a CI run, failtriage reads the test report, removes secrets and personal data, groups the failures by root cause and classifies each group as `product_bug`, `test_bug`, `flaky`, `environment` or `unknown`. It posts one report on the pull request, with the lines each verdict is based on. Fixed rules go first and an LLM second. Without an API key the rules do all the work.

Use it as `dimagrotser/ai-test-failure-triage@v1`, or pin `@v1.0.0` or the commit SHA of this release.

## Inputs

| Input | Default | Meaning |
|---|---|---|
| `junit` | none | JUnit XML reports, one path per line |
| `playwright` | none | Playwright JSON reports, one path per line |
| `allure` | none | Allure results directories, one path per line |
| `github-token` | `github.token` | token for the GitHub API |
| `anthropic-api-key` | none | enables LLM classification |
| `model` | `claude-sonnet-5-5` | model that classifies the groups |
| `comment` | `true` | `false` keeps the report in the job summary only |
| `comment-key` | none | name of the comment, to keep several per pull request |

Set exactly one of `junit`, `playwright` and `allure`. Several files of one format are fine.

## Outputs

| Output | Meaning |
|---|---|
| `report` | path of the JSON report |
| `groups` | number of failure groups |

## Permissions

```yaml
permissions:
  pull-requests: write
  actions: read
  contents: read
```

The action stops with an error on `pull_request_target`.

## Known limits

- Only JUnit XML, Playwright JSON and Allure result files are read. Allure steps and attachments do not reach the LLM.
- Fork and Dependabot pull requests get no comment and no LLM call, because GitHub gives them a read-only token and no secrets. The report goes to the job summary and the verdicts come from the rules.
- History comes from an artifact that runs on main upload. A repository needs a few such runs first, artifacts expire with the retention setting, and until then the report says `History: none`. A truly intermittent failure with no retry can come out as `unknown`.
- At most 10 groups per run go to the LLM, the rest are classified by the rules only. A run costs up to about $0.07 with Sonnet.
- Accuracy is a rough guide. On 48 labeled groups from a small test app I wrote, the rules get 58% right and the rules plus Sonnet get 60%. `product_bug` is the weak spot at 44%. The dataset has no real failures. I could not compare Haiku, because its calls failed in the eval run. See [docs/lab.md](../lab.md).
- Two jobs running the action on main in one workflow run collide on the history artifact name, and the second upload fails.
