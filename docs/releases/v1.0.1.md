# failtriage v1.0.1

Changes since v1.0.0. Inputs, outputs and permissions stay as they were, see the [v1.0.0 notes](v1.0.0.md). `@v1` moves to this release. You can also pin `@v1.0.1` or the commit SHA.

## What changed

- **The log says why an LLM call failed** (#74). A group whose call fails still gets the verdict of the rules. The log line now carries the reason, for example `the request failed: AuthenticationError, HTTP 401`. Before it said only `ProviderError`, which looked the same for a revoked key, a rate limit and a network error.
- **The LLM gets a diff when the stack trace names no changed file** (#75). Until now only the diff of files named in the trace was sent, so an end-to-end test, which names its own file and not the app code, got no diff at all and the answer was often `unknown`. Now it gets the first 150 lines of the whole diff, behind a line that says the match was not by path. On the eval Sonnet got 36 of 49 groups right, against 27 before the change. Read that with the caveats in [docs/lab.md](../lab.md): one run each, seven of the ten groups that improved belong to two cases, and one group got worse.
- **Retries from `pytest-rerunfailures` and `flaky` are read** (#76). These plugins write a failed attempt as a testcase with no outcome, so a flaky test looked like a plain pass. When a suite has more testcases than its `tests` count and the extra ones are exactly the earlier copies of repeated testcases, those copies are now failed attempts, and the group is `flaky` with high confidence. Any other mismatch changes nothing.
- **The eval dataset has its first real case** (#35, #75). `real-preview-item-title` is a failure from another repository, labeled by hand, and a real case can now carry its diff.

## Known limits that changed

- Accuracy is still a rough guide. On 49 labeled groups, 48 from a small test app I wrote and one real failure, the rules get 57% right and the rules plus Sonnet 73%. Each configuration ran once. Before the diff change Sonnet was one group behind the rules. It is still worse than the rules on `flaky` (4 of 7 against 7) and on `environment` (6 of 9 against 8).
- I still could not compare Haiku. `claude-haiku-4-5` made no successful call in the eval and I have not found out why.
- A group whose trace names no changed file costs a little more, about $0.0076 per group with Sonnet instead of $0.0073, and a large pull request can push the relevant file out of the first 150 lines.
- `pytest-retry` leaves the failed attempt out of the report, so a test it retried looks like a plain pass and cannot be called flaky from that run.

Everything else under "Known limits" in the v1.0.0 notes still applies.
